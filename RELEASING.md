# Release protection checklist

Publishing is forbidden until a maintainer has verified every control below. The workflow file documents the intended release path; it does not configure GitHub rulesets, environments, npm trusted publishing, or account permissions by itself.

## One-time repository controls

- [ ] The repository is public and its canonical slug is exactly `TheMochiApp/mochi-cli`.
- [ ] A GitHub ruleset protects `v*` tags, restricts tag creation to release maintainers, applies to administrators, and has no bypass actor or admin bypass.
- [ ] The GitHub `production` environment requires approval from a reviewer other than the person dispatching the release, has “prevent self-review” enabled, has no administrator bypass, and restricts deployment to protected `v*` tags.
- [ ] npm trusted publishing for `@themochiapp/cli` is configured with organization `TheMochiApp`, repository `mochi-cli`, workflow filename `publish.yml`, environment `production`, and only the `npm publish` action allowed.
- [ ] The npm package and organization contain no automation token for this workflow. GitHub repository, organization, and `production` environment secrets contain no npm publish token or `NODE_AUTH_TOKEN`.

## One-time first-publication bootstrap

At the time this contract was written, the read-only command `npm view @themochiapp/cli --json` returned `E404`. npm does not expose trusted-publisher configuration until the package exists, so the first publication is a narrowly bounded human bootstrap outside this repository and outside GitHub Actions. Codex and CI must never perform this bootstrap automatically.

Only a maintainer with `@themochiapp` publish permission and enforced npm web/2FA authentication may perform it:

1. Run `npm view @themochiapp/cli --json` again. Continue only if it returns `E404`. If the package exists, stop, inspect its owner/provenance on npm, and do not overwrite or “re-bootstrap” it.
2. Confirm the exact public repository, `v*` ruleset, and protected `production` environment above already exist. Work in a new temporary directory that is not a clone, worktree, or child of any Mochi repository. Confirm the directory contains no `.npmrc`, `.env`, credential, source, build, or package-lock file.
3. Create only a short placeholder `README.md` and this exact `package.json`:

   ```json
   {
     "name": "@themochiapp/cli",
     "version": "0.0.0",
     "description": "Bootstrap placeholder; no executable code.",
     "license": "UNLICENSED",
     "private": false,
     "files": [],
     "scripts": {},
     "repository": {
       "type": "git",
       "url": "git+https://github.com/TheMochiApp/mochi-cli.git"
     },
     "publishConfig": { "access": "public" }
   }
   ```

4. Run `npm pack --json --dry-run --ignore-scripts`. Inspect the reported name/version and every file. It must be `@themochiapp/cli@0.0.0`, contain only `package.json` and the placeholder `README.md`, and contain no code, lifecycle script, dependency, token, credential, environment file, or generated artifact. Stop if the inspection differs.
5. Run `npm login --auth-type=web`, complete the browser and 2FA challenge, then run `npm whoami`. Never create, paste, save, or add an automation, classic, or granular npm token to a file, shell command, GitHub secret, environment, or CI job.
6. From that inspected temporary directory only, run `npm publish --ignore-scripts --access public`. Do not use a tarball, manifest, or command generated by Codex or CI for this bootstrap.
7. Run `npm logout` immediately. Confirm `npm view @themochiapp/cli@0.0.0 name version repository scripts dependencies --json` shows the expected placeholder identity, exact repository, and no scripts or dependencies.
8. In npm package settings, configure the trusted publisher exactly: organization `TheMochiApp`, repository `mochi-cli`, workflow filename `publish.yml`, environment `production`, and the `npm publish` action only. Re-check the GitHub environment protections above.
9. If desired, a maintainer may use a new interactive web/2FA session to run `npm deprecate @themochiapp/cli@0.0.0 "Bootstrap placeholder; install a current release."`, then must run `npm logout` again. This optional step must not use a token or CI.

Publication is forbidden until the package exists and every repository, environment, and trusted-publisher control above is configured and independently verified. All real versions are published only by the protected OIDC workflow; the bootstrap is never repeated.

## Every release

- [ ] CI and the live OpenAPI contract are green on the release commit.
- [ ] `package.json` has the intended version and the protected annotated or lightweight tag is exactly `v<package version>` at that commit.
- [ ] In **Publish npm package**, the maintainer must select that exact protected `v*` tag in GitHub Actions “Use workflow from” and enter the same tag in the `tag` input, because environment tag restrictions evaluate the workflow run ref, not the checkout ref; the workflow rejects any mismatch.
- [ ] The dispatching maintainer does not approve their own production deployment.
- [ ] The verification job succeeds before the production reviewer approves the isolated OIDC publish job.
- [ ] The published package is public, has npm provenance, and contains only the five-file release allowlist reported by the workflow.

The verification job executes repository code without OIDC permission, builds a scripts-disabled tarball, and records its SHA-256. The protected publish job has no checkout and executes no repository or dependency scripts; it receives only the verified tarball and checksum before requesting the short-lived npm OIDC identity.
